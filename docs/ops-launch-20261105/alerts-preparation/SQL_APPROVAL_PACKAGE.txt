RLS/schema compatibility

Preflight requires the exact existing outbox column types, RLS and dedupe_key
NOT NULL. A first apply aborts on ANY existing reserved-purpose/prefix record,
before it can hide/freeze a legitimate row. On exact retry, existing reserved
rows must match the validated immutable aggregate key. Active alert admission
also prevents re-preparation.

Four NULL-safe RESTRICTIVE policies reserve the new purpose/prefix for SELECT,
INSERT, UPDATE and DELETE. Existing rows with absent/null purpose continue
through their current policies. Hiding reserved rows from ordinary SELECT also
prevents an existing app lease subquery from selecting an inaccessible ops row
and starving ordinary messages. No existing permissive policy/grant is weakened.
The source leaseOutboxRecord query independently excludes only the reserved
purpose/prefix, including when called by an operator who bypasses RLS.

Dispatch/recovery semantics

Claim is atomic, SKIP LOCKED and bounded. Pre-dispatch leases may be reclaimed
under the existing five-attempt bound. Only the exact current lease can fence
or settle. Fence persists before any Graph request; duplicate fence returns
false. No dispatched job can be leased again. Expired dispatch becomes dead /
unknown with audit evidence. Expired/unfenced work is held after its bound.
Graph202 means provider accepted, never verified inbox delivery. Any ambiguous
send or post-send DB outage remains held; no blind resend. Completed settlement
retry is idempotent. Closing admission blocks new claims/fences but still permits
valid in-flight outcomes to settle. Customer balances, holds, purchases, cards,
Auth messages and financial journals are outside every mutating query.
