# Model feature registry — Phase 5C

Research permission and model activation are separate. `research-features.ts` defines immutable feature versions in DISPLAY_ONLY, MODEL_ELIGIBLE and MODEL_ACTIVE states. Governance and actor/MFA checks belong to the server/database layer; accepting a valid JSON shape is not permission to register or activate it.

Each definition binds exact fact types, a structured-sporting-input kind, transformation ID/version, causal rationale and limitations, accepted confirmation level, maximum age, review/effective interval and review reference. Eligible/active features additionally require an exact model version/configuration hash and a non-future training cutoff. State/configuration changes create new retained versions. There are no default active player-impact, news, injury, lineup or weather coefficients.

The computational definition hash is separate from the full audited registry-row hash. It binds feature ID, sporting kind, sorted fact/confirmation types, transformation ID/version, rationale, limitations, freshness and training cutoff. It excludes state, row version, model binding and review clocks, which remain in the full hash. A model can therefore freeze the computational definition before a later reviewed activation binds back to that model, without a circular model-hash/feature-hash dependency. Any computational change changes the definition hash and requires a new model configuration.

Market prices, bookmaker movement, implied probability, community opinion, article prose and LLM-generated probabilities have no fields in the accepted input contract. An explanation may describe a proposed sporting mechanism; it is not a measured contribution. `explainResearchFeatures` returns numericalContribution=null until a separately reviewed fitted executor supplies actual contribution evidence. The current Football V1 estimator is still NOT_CONFIGURED.

`assessResearchRecalculation` evaluates current active definitions against changed, correctly mapped facts before kickoff. It applies source model/derived/commercial/retention permissions independently of public-display permission, current source versions, as-of knowledge, confirmation, freshness, withdrawals and unresolved conflicts. Display-only changes return NO_ACTIVE_FEATURE_CHANGE. Unavailable or conflicting active inputs return BLOCKED_DATA. Eligible changes with no estimator return MODEL_NOT_CONFIGURED. No branch returns probabilities, changes a prior prediction or creates a tip.

ELIGIBLE_FOR_RECALCULATION is a request boundary, not model execution. Its hash binds trigger evidence/configuration for request deduplication, not a fitted model's complete input snapshot. A future executor must build and validate the complete sporting input bundle, verify its implementation/source authority, and record the old/new prediction lineage, causal trigger IDs, cutoff, actor/job and calculation time. It must preserve Phase 5B's one canonical prediction per event/model/decision window for calibration; repeated research updates cannot silently give a match extra weight. An explicit reviewed lineage policy and fitted executor are prerequisites, not delivered activation.

Pure regressions cover inactive vs active changes, source revocation, private model rights vs public display, future/stale/rumour evidence, preserved previous prediction ID and rejection of probability/market overrides. Authored test feature names do not identify installed models.
