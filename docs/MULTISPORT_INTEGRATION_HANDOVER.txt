Compatibility and confirmed repairs
- Service transport remains schema_version 1.1; app scoring remains the existing
  schemaVersion 1 contract. Translation joins them without another scoring engine.
- Service epl/nba map explicitly to app football/basketball and scorer
  epl/basketball. AFL and NRL identifiers remain unchanged.
- Provider IDs remain strings; canonical player/fixture/team IDs remain stable.
  A reviewed binding supplies existing Docked IDs. Names and array order are never
  identity keys. Duplicate Docked identity bindings now fail in the service.
- Raw roster updates now carry the requested season. Approved AFL positions use
  BACK/MID/FWD/RUCK; NBA supports reviewed multiple positions. The application
  translates source rosters into its existing review workflow. Unknown jerseys
  remain null; injuries do not retire contracted players. Synthetic rosters are
  rejected by the authorised bridge. Roster readiness never authorises issuance.
- A dangerous source-facing eligible_for_new_issuance flag was removed as an
  automatic consequence of roster completeness. It now remains false; separate
  roster_review_ready describes evidence readiness. Docked release gates decide
  issuance. Existing player assets are untouched.
- NBA and NRL raw inputs were previously always pending in Docked's integration
  mapper. They now map to the existing versioned scorers. NRL's raw field registry
  now includes all 25 required scoring events (27 total raw fields). This does not
  invent a provider implementation or approve those proposed competition rules.
- EPL accepts optional versioned ordered-event evidence, using the existing
  regulation-time/on-pitch validator and approved assist definition. Basic box
  scores alone remain pending. No minutes-to-seconds or outfield-concession guess.
- Confirmed DNP can carry null raw fields and resolves through the existing zero
  treatment. Missing rows, unknown participation, partial/current=false fields,
  withdrawn records and contradictory nonzero DNP evidence remain pending.
- First authoritative final observation is retained as completion_observed_at.
  elapsed time, zero minutes and a new gameweek do not establish completion.
- Raw receipts, current projections, recalculation requests and cursor advancement
  are transactional. Dataset changes require reviewed resync; stale/overlapping
  pages, conflicting equal revisions and wrong sport/entity provenance fail.
  Exact retries are idempotent. No browser-accessible raw write endpoint exists.
- A separate trusted refresh bridge uses the existing frozen mapping, permit,
  scoring journal, centipoints, aggregation and late-correction controls. Raw
  delivery cannot approve a ruleset, create a competition or mint cards.
