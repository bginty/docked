## Implemented provider fetch and processing

Fixed-host, header-authenticated GET adapters: Sportmonks fixture with lineups/details/events/state/periods/participants and current domestic squad with player/team/position; SportsDataIO PlayersByAvailable and BoxScoreFinal/ScoreID. Redirects rejected, response/time limits enforced, no arbitrary URLs, credentials omitted from query/logs and credential-echo bodies rejected. Every attempted fetch consumes a durable daily budget. Worker jobs use database leases, bounded exponential backoff, max six attempts, rights review before access, and explicit blocked state. No continuous polling enabled.

Raw payload versions retain provider, resource hash, body hash, source-rights evidence, observation and licensed expiry; identical payloads deduplicate. The reconciliation step binds raw resource/fixture/player mapping, appends a new immutable scoring revision only when data changes, reuses Docked's scoring rules and preserves locked entries. Real-source and simulation streams remain separate. No client write endpoint or public role gets access. Schema installation and scheduler activation remain a controlled operator step after source approval. Raw purge must retain provenance/hash and respect the permitted retention schedule; never silently delete scoring history.

## Field coverage — do not reduce the rules to fit the feed

**EPL:** exact regulation seconds separately from added time; played seconds; goals, assists, total/penalty saves, missed penalties, own goals, yellow/red/second-yellow state; concessions during ordered verified on-pitch intervals. Sportmonks exposes minute/extra_minute/sort_order and per-player details, but current documentation does not establish exact boundary ordering, regulation seconds or equivalence to Docked's deliberate-assist rule. Current adapter stores the real source state and produces **pending player data**, not guessed clean sheets or appearance brackets. No whole-team conceded total substitute.

**NFL:** PassingYards, PassingTouchdowns, PassingInterceptions, RushingYards, RushingTouchdowns, Receptions, ReceivingYards, ReceivingTouchdowns, FumblesLost, TwoPointConversionPasses/Runs/Receptions, KickReturnTouchdowns and PuntReturnTouchdowns map to existing coefficients. **OffensiveFumbleRecoveryTouchdowns is deprecated in the official dictionary.** The adapter does not trust it or fill zero. A reliable event-attribution feed and a versioned tested derivation are still required before the player can be complete. Confirm Played/DNP/bye semantics independently; a missing row is pending, never zero. SportsDataIO times are US Eastern; convert with timezone/DST validation. Do not use provider FantasyPoints/FanDuel/other platforms' totals.

No scoring rule change is made here. If suitable evidence is unavailable, the explicit alternative is a **new prospective ruleset** removing offensive fumble-recovery TD points and/or defining EPL provider-aligned appearance/assist/on-pitch rules, with owner approval and clear disclosure. Existing locked competitions must never change. Recommended first action is provider clarification, not approval of a weaker ruleset now.

2. Store keys in the **dedicated Docked operator worker's server secret store**, separate from the member web runtime: `SPORTMONKS_API_TOKEN` / `SPORTSDATAIO_API_KEY`. For local setup use ignored `private-data/sports-feed/` with owner-only filesystem access, not committed `.env` files. Never use NEXT_PUBLIC_, APK config, URL parameters or a hosting bypass secret. Supply just “configured” and the evidence location. Existing keys are not permission. The worker is currently an injectable server module, not a deployed cron endpoint; do not add provider secrets to the current member app.

7. Only then enable the durable worker at a quota-reviewed cadence, with source-health monitoring and alerts to the operator. Deploy scoped read models to the app, run actual hosted two-account acceptance, then the authorised domain cutover. No invitations without named recipients and sending authority.
