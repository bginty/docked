# Team trends — Phase 5C

Initial match research is EPL pre-match regulation 1X2. The reusable trend arithmetic has no installed dataset or default fitted parameters. Football V1 remains NOT_CONFIGURED. A detailed research file or positive descriptive trend cannot activate it.

Each trend policy identifies the team, competition, season, metric, unit, HOME/AWAY/ALL context, opponent-adjustment status/version, recent and baseline windows, optional last-N/time decay, minimum matches/minutes and threshold. Missing context or mixed competitions does not become a comparable average. Observations known or ingested after the requested cutoff are excluded. Duplicate events are rejected, so corroborating sources do not inflate the sample.

The output records decimal means, differences, sample counts and available exposure; fact IDs, excluded observation IDs, policy version/configuration hash and as-of time make the descriptive calculation reproducible. The explicit overlap policy is either DISJOINT or RECENT_INCLUDED_IN_BASELINE. A season-to-date baseline can contain recent matches, with both sample counts and the overlap disclosed; shared matches are not extra independent observations. Empty samples yield unknown numerical outputs. A zero baseline does not generate an infinite or invented percentage. Labels use the declared threshold only; no claim of significance or confidence interval is manufactured.

Match research separates recent form, home/away context, attack/defence, licensed xG, availability, lineups, rest/schedule, weather/venue and results. H2H has an explicit unavailable section until authorised mapped evidence and a suitable adapter exist. None of these sections is silently treated as an active model feature. The match completeness label refers to the explicit required-fact/freshness policy, not a percentage of every possible fact or a probability-quality score.

Raw unadjusted differences are labelled DESCRIPTIVE_ONLY. Opponent-adjusted measurements require the same declared adjustment version; this release does not invent an adjustment algorithm. A future model must separately validate any transformation, preserve its training cutoff/configuration, and record prospective estimates through the existing independent-model ledger.
