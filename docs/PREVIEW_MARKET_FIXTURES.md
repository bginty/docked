# Preview market fixtures — Phase 4.5

This is a synthetic interface exercise, not provider data or strategy validation. Every option, review and saved record carries **DEMO / PREVIEW PRICE**. The authored fictional football and basketball events simulate a start two hours after review. They are never described as genuine upcoming fixtures.

The arithmetic calls the existing `buildMarketReference` in its existing research mode, which already accepts explicit fixture provenance. Source groups, complete-market normalisation, independent lower-median availability and rounding are unchanged. The wrapper immediately produces `evidenceMode: preview`, `fixture: true`; that type is incompatible with a genuine current/research MarketReference. Synthetic standard/rights flags exist only inside this authored exercise and do not assert real licensing or provider verification. The same source vectors are rejected in current mode.

Access requires the exact hosted Docked Preview configuration/project, a verified live same-user Auth session, an active community profile, legal-age/terms declarations, separate privacy acceptance and an unexpired, unrevoked server-granted `preview_market_fixtures` capability. User metadata and the visual composer toggle cannot grant it. Production, other projects and ordinary member requests fail closed. The helper and database trigger both enforce the capability; final submission checks again after locks.

`POST /api/preview-edges` accepts only review selection or the immutable review ID/hash, explicit permanent confirmation and idempotency key. No typed odds, provider name, result or personal price is accepted. Reviews expire after 90 seconds. A server-side rebuild must match the entire saved canonical payload hash. Submission is serialized per durable profile, duplicate retries reuse the same record, and database uniqueness prevents a second entry. Changing a selection requires a new review/confirmation.

`private.preview_market_sessions` and `private.preview_fixture_edges` are separate, RLS-enabled, browser-revoked, append-only tables. No canonical event/market/reference/community Edge/social-post row is created. There is no settlement, prize, points or ROI field and no join from real Top Docked, competitions or official results. The real current-provider engine also rejects fixture provenance. There is no export/import adapter that promotes these tables. Do not add one. The API is private/no-store/noindex; no public fixture route or sitemap entry exists.

Only the latest 20 own preview records are returned; no global test leaderboard is implied. The minimal durable profile ID remains after account pseudonymisation; no email, real name, password, free-form reasoning, personal price or upload is retained in these immutable rows. A future synthetic fixture version must retain its old decoder; never reinterpret a previously stored payload under new fixture arithmetic.

The separate `preview_top_docked` capability opens an explanatory preview screen at `/top-docked` before any real leaderboard query runs. It accepts no performance input, shows no invented score or rank, and explains the published genuine qualification rules. The real `/api/top-docked` still requires genuine regional permission.
