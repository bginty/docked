WHY THE LIVE BUG REMAINED
The earlier player-detail navigation fix was kept separate from the foil
artwork release and was absent from Production 5e043af5. The old parent
onViewCard callback called closePack before displaying player details, which
unmounted the entire reveal. The card viewer could therefore only return to
pack history. This was reproduced in the genuine signed-in live browser with
an already-opened nine-card receipt before making the correction.

CORRECTED BEHAVIOUR
The mounted pack owns its player-detail sheet. Tapping the player, View Player,
Back to Pack, the detail Close button and browser/native Back retain the same
card, revealed phase and remaining cards. Next Card stays prominent; the final
card offers View Pack Summary. Existing share and animation features remain.

An unfinished pack cannot exit through Close, backdrop, Escape or Back without
an explicit decision. Continue revealing returns to the same card. Skip All &
Exit intentionally ends the presentation. Fully revealed/final summary flows
can close normally. Browser Back veto restores its consumed modal history
entry, preventing repeated Back from escaping underneath the confirmation.

The live visual check caught a CSS conflict: the mobile pack layout's explicit
display:flex overrode the native hidden attribute on the retained reveal.
The follow-up be8dea39 scopes display:none to the hidden pack section. Tests
now assert both the confirmation and the absence of the hidden Next Card UI.

Minimal local progress stores index, revealed and timestamp, scoped to member
and authenticated receipt. Resume uses existing issued cards. Explicit replay
does not overwrite an unfinished ordinary reveal. Storage failure does not
break in-memory navigation.
