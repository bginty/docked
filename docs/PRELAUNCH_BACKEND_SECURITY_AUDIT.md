## Existing controls inspected

- Authentication: `auth.ts` obtains the session token then verifies it with `getUser`, requires confirmed non-anonymous identity, checks current admission/profile restriction and active `auth.sessions`, and derives subject/session/AAL from verified-token claims. Privileged `requireRole` rechecks database roles and requires AAL2. User-editable metadata does not grant a staff role in these paths.
- Social: `withCommunityActor` establishes server-derived transaction-local identity/session/AAL and invokes the database actor gate. Collection visibility and blocks are checked by database helpers. Card posts retain immutable snapshots; direct anonymous/member table privileges are denied in the existing migrations/tests.
- Wallet/ownership: `CreditsSandboxStore.execute` takes the shared advisory lock and state row lock, reauthorises within the transaction, obtains server time, executes the existing idempotent command, validates intermediate state and writes journal/history/state atomically. Lineup submissions use the same lock ordering. Retried calls retain receipts rather than issuing twice.
- Marketplace: member test wallet requires active beta admission; owner operations require MFA. Both parties are rechecked inside mutation authorisation, collection visibility is checked for affected cards, and test-market read-only/offer activation gates remain in force. `privateOfferEnabled` rejects hosted/production and non-loopback databases. No new trading activation is performed.
- Redemption: existing tests cover non-redeemable test/promotional credits, exact integer conversion, reservation/spend exclusion, claims, ambiguous outcomes, returns, role segregation, ciphertext-bound bank snapshots and private projections. Passing synthetic fixtures is not real-money readiness.
- Lineup secrecy: `social_locked_lineups` requires admitted visible profiles, explicitly approved publication policy, server deadline, every configured slot locked and kickoff reached, and visible standings. It reads locked snapshots. Partial rolling lineups stay hidden. No current ownership projection reveals lineup selections.
- Recovery: application rollback cannot roll back transferred ownership or a ledger transaction. Restore only in an isolated environment, compare ledger conservation/serial uniqueness/entry snapshots, reconcile external systems before any future live recovery, and retain immutable incident evidence.
