- All database tests use disposable local databases. No hosted mutation, production pack opening, purchase, lineup edit or ownership cleanup was performed.
- `platform-tests.txt`: 454 cases, 451 passed initially. Three release-tool tests could not initialise temporary Git repositories under sandbox restrictions. `release-tests-retry.txt` records all three passing outside the sandbox. These were not application assertion failures.
- The first clean build stopped before compiling because Windows denied creating the isolated build directory's `node_modules` junction (`EPERM`). It passed outside the sandbox. `build.txt` and `client-boundary.txt` contain the successful final run. That run uses synthetic server-secret canaries and no real credentials. This is a browser-boundary check, not a claim of a complete repository secret audit.

- The first expanded browser interaction test timed out looking for the visible label “Reveal all / Skip”. The actual accessible button name is “Skip remaining reveals”. The locator was corrected to the observed accessible name; the final four-width run passes Reveal All, Escape, retained card count and body-overflow cleanup. No product control was changed to satisfy the test.
- One formatter attempt reported a transient Windows file-open error on `weekly-core.test.ts`. The subsequent formatting run succeeded; the database test itself passed on both runs.
- The local saved-receipt viewer uses actual copied/cleaned test-card data with the real shared component. It is not a signed-in hosted acceptance journey, a full restored production schema, or a physical Samsung device test.
- The local cleanup is an atomic PGlite audit mirror transaction plus pure domain validation. The prepared eligibility migrations are separately tested against the full local migration chain. A production-schema asset-removal migration is deliberately not supplied as executable approval-free cleanup; current immutable projection guards require a reviewed archive transition.
