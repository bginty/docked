Candidate implementation
src/core/nfl-round-calendar.ts provides a deterministic readiness plan from the
complete calendar, not the latest statistic. It checks the current approved
272-game/32-team/17-games-per-team regular-season shape, unique fixtures and
teams, explicit kickoff times, freshness, existing mode streams and provider
authorisation expiry. Unknown kickoffs fail closed. The calendar hash is stable
under row ordering and changes if the underlying calendar changes.

scripts/nfl-calendar-readiness.ts is read-only by default and can be run by the
existing authorised operator infrastructure without adding a paid service:
  npx tsx scripts/nfl-calendar-readiness.ts --season 2026
It downloads the existing configured source only while the current scoped
provider permission allows it, reads registered streams and writes a local
readiness report. It does not publish or edit competitions.

After reviewing the exact plan, and only after release approval, the operator
can prepare ONE wholly future round with the same tool:
  npx tsx scripts/nfl-calendar-readiness.ts --season 2026 --prepare-drafts
    --round N --plan-hash EXACT_REVIEWED_SHA256
The command requires a matching current calendar hash, authorised coverage
through the last kickoff, recent active verified player mappings, both teams
mapped in each fixture, the existing immutable NFL seven-card rules and the
original whole-round entry deadline. No real round was prepared in this task.

The existing registerNflRound transaction now supports an explicit draft option.
Drafts have disabled entry/standings controls, no production_rounds publication,
and next_check=infinity so the collector cannot process them. The journal records
that they are unpublished and collection is paused. Existing caller behaviour
is retained. The existing advisory transaction lock and unique stream constraint
prevent duplicate registrations. Retrying preserves existing rule snapshots;
retrying with a publication option cannot publish a pre-existing draft.

Publish only through a separately reviewed owner action before the entry
deadline, after verifying roster, calendar, collection rights, eligibility,
rules and deadlines. That action must explicitly enable the intended controls,
publication and collector together. Never publish a missed deadline; prepare
the next eligible calendar round instead. No auto-publication, SQL permission
change, new migration, cron change or production deployment is part of this
candidate. The operator can schedule the read-only readiness command in existing
CI/operations after approval; no background job is silently enabled here.
