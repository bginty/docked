Existing confirmed member -> ordinary public onboarding
5-6 November 2026, Australia/Sydney

Established defect

The nominated reviewer has a confirmed Auth identity and beta namespace profile
and consent, but no ordinary public profile. Profile-backed identity() prevents
/app/onboarding from rendering the form that creates that missing record. Signup
correctly refuses to replace an existing Auth identity. This is a circular route
dependency, not a reason to copy beta consent or create another account.

Implemented; deployment and actual member submission remain separate

Two independently gated routes let an admitted existing member explicitly set up
their own ordinary public profile while global public mode remains disabled:

GET /app/onboarding/public
POST /api/auth/public-member-setup

Required server-only configuration:
DOCKED_PUBLIC_MEMBER_SETUP=true
DOCKED_PUBLIC_MEMBER_SETUP_POLICY_APPROVED=true
LEGAL_ENTITY_VERIFIED=true
DOCKED_PUBLIC_TERMS_VERSION=2026-11-02-release-preparation-v2
DOCKED_PUBLIC_PRIVACY_VERSION=2026-11-02-release-preparation-v2
DOCKED_PUBLIC_MEMBER_SETUP_DATABASE_URL=<existing restricted docked_app URL>

Entity verification is independent of policy-text approval; neither proves
third-party licensing or regulatory clearance. Unset/false bindings fail closed.
No global public-customer, registration, gameplay, payment, withdrawal or prize
flag needs to be enabled for this setup form.

The existing beta requireIdentity() admission, confirmed session and MFA boundary
is preserved. A separate existing restricted ordinary docked_app connection is
used because the beta mapper/role deliberately cannot access ordinary records.
No new grants, Auth administration, BYPASSRLS, migration or role projection is
introduced. Only the restricted database URL is required. The neighbouring
privileged service secret is not used or copied.

Ordinary read state runs in a read-only transaction with its own subject,
session and AAL claims, and checks active confirmed Auth/session and ordinary
role MFA. The write path rechecks session, roles, disabled profile and latest
approved AU adult eligibility transactionally. Profile creation reuses existing
retry-safe persistInvitedProfile with advisory locking. Existing ordinary
profiles are not silently renewed or rewritten. Legacy beta roles and ordinary
staff roles are not created or copied. Privileged endpoints retain their
existing role and MFA checks.

The existing AppOnboardingForm uses a fixed scoped endpoint and return URL,
Terms /commercial-policy and Privacy /privacy. Location/username are personally
entered; age, Terms and privacy choices start unticked. Beta age, location and
consent are never copied. No password, Auth identity, wallet balance, permanent
inventory or entry is created by the form. Exact /app/onboarding/public is an
MFA-return allowlist entry; external/query destinations stay rejected.

The later normal public-mode /app/onboarding path is also corrected using an
onboarding-only verified own-session helper. Normal gameplay/wallet identity
and requireRole stay profile-backed. Verified enrolled factors and ordinary
owner/staff roles require AAL2 even when the ordinary profile is absent.
Identity, provider and role lookups fail closed.
