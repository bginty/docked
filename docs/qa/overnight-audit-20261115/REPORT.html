C. TEN BIGGEST PROBLEMS, IN CUSTOMER-IMPACT ORDER

1. Pack confirmation can outlive the 15-second browser deadline. CONFIRMED. The live beta wallet UPDATE averages 8.51s over 94 calls and reaches 16.56s; the warm /api/test-wallet p95 is 16.58s over the recent mixed-release window. The 4.18MB aggregate is validated/projected inside a globally ordered wallet transaction. A timeout can appear after a successful commit. The screenshot's 700-credit purchase was reconciled earlier: exactly one Premium 1 AFL card, not nine cards, with no missing asset or duplicate debit. Do not refund or reissue it merely because the screen timed out.
2. Play loads data that is too broad for the initial screen. CONFIRMED COST; the exact gain from splitting it remains to be measured. member_review_context averages 3.82s across 477 calls; production_read_state averages 2.00s across 260 calls. The server runs these plus status/jersey and member reads serially. Review context constructs all owned-card history from the large aggregate even when the user only needs the current lineup. Its wrappers also accumulate older data shapes. My Cards has its own paginated reader; do not incorrectly attribute this complete Play path to every tab.
3. A legitimate allocated beta pack can still encounter the old freshness condition when revealing. CONFIRMED IN THE PENDING REPAIR'S ISOLATED TEST. New issuance now uses the stable catalogue, but the old reveal path checks live-roster eligibility again. The pending candidate removes that dependency only for the registered founder-credit-season policy. Revealing a saved receipt must never allocate another card. No additional Production opening was performed to reproduce it during this audit.
4. The NFL selector is a list of imported competitions, not a complete season calendar. CONFIRMED by source and fresh read-only data. Member rows include Round 6, Round 7 and synthetic Practice Round 1. That explains the screenshot. The pending 18-round calendar is not live. Its retained 272-game schedule was verified on 8 November; 24 later kickoff times remain TBD. Displaying a full calendar must not invent current fixtures, open entries, enable scores or conceal Practice restrictions.
5. Auto-fill stops being useful once a team is established. CONFIRMED IN SOURCE. recommendOwnedLineup explicitly rejects established teams and tells the user to replace players manually. The pending solver addresses empty slots in both Traditional and All-Star, preserving manual choices, locks, ownership, position/FLEX eligibility, unique players and the salary cap. It is not live.
6. High-tier reveal effects are too expensive on the simulated slower device. LAB RESULT, not an Android-device FPS claim. CPU 4x tests measured Ultra Rare 14.5fps, Legendary 13.3fps and Icon 10.9fps, despite economy quality selection. At normal CPU, those tiers were about 51/43/42fps. The idle baseline was 60fps. Reduce canvas/effect work while keeping the card and reveal controls immediate.
7. Every public route carries broad application styling and substantial JS. CONFIRMED DOWNLOAD/SOURCE FINDING. Each tested route downloaded ~78KB encoded CSS, 338KB decoded. Login downloaded ~189KB encoded JS, 608KB decoded; the anonymous cards recovery route ~276KB/873KB. Root imports include owner, marketplace, fantasy and cinema CSS on public/auth pages. Some observed JS is prefetch traffic, not one initial bundle. Pack opening already uses lazy imports and intent preloading; preserve those existing improvements.
8. Returning to the app interrupts collection inspection. CONFIRMED UI REPRO. Opening a card, then firing window focus closes the detail panel on all three sports at desktop and mobile widths. The invalidation handler clears detail, filters' cursor and cached validation before refreshing. Native resume also triggers route refresh, session verification and component listeners. Keep ownership/access revalidation, but preserve safe reading position and coalesce redundant refreshes. Never retain another member's private cache after logout.
9. Phone verification can remain disabled indefinitely on a stalled response. CONFIRMED SOURCE + ISOLATED UI REPRO. The component uses raw fetch without an abort deadline. At 17 seconds it still showed disabled “Please wait…” and no alert. A finite provider error does recover correctly; code autofill and change number work. This is a pre-SMS-test fix, not evidence that an SMS was sent.
10. Acceptance evidence is fragmented and several historical fixtures are stale. CONFIRMED TESTING GAP. Old tests expected hidden NBA, old pack classes, old composer labels and the former Profile weekly-pack location. One incomplete mock response crashed a fixture; supplying the current disabled API contract resolved it without modifying the app. Missing physical v31 acceptance and authenticated current-release timings remain material gaps. Tests must bind to current contracts and record the source/environment they actually test.
