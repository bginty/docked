## Why paid sales cannot open

The five-minute Google scheduler would never reach the commercial worker under the reviewed environment. The inherited `DOCKED_GOOGLE_RECONCILIATION_ENABLED=true` selects the old beta worker first. Its public-mode guard throws synchronously when the two beta flags are false. The dispatcher invokes each function while building its list of promises, so the exception prevents the commercial callback from starting. The isolated test ran the exact production dispatcher and real beta guard with the final flag values. It recorded one beta invocation and zero commercial invocations. Periodic checks of known purchases therefore cannot cover missed refund events under this package.

The reviewed environment supplies the legacy receiver's audience, service account and subscription. It supplies none of the three corresponding commercial receiver bindings. The commercial HTTP handler compares the request URL to the empty audience and returns 401 before verifying or queueing any notification. The configured legacy audience names the beta endpoint, which also rejects public mode. The existing verifier's read-only subscription metadata request returned 403, so this run cannot independently identify Google's current push destination from Cloud Pub/Sub. This does not affect the independently reproduced scheduler failure.

If sales opened under these settings, a store refund could go unprocessed and its credits could remain spendable. November's real TEST purchases, refunds and financial ledger evidence still stand. The failure is in dispatching work under the final environment.

Keep both beta modes disabled. Select the commercial worker independently of the retired beta worker, and ensure a synchronous failure in either registered worker cannot prevent dispatch of the other. Reconcile the existing Google subscription destination, OIDC audience, signer and subscription name through an authorised read. Route authenticated events for that exact subscription to the commercial queue when commercial service is active. Preserve signature, issuer, audience, account, subscription, receipt and TEST-versus-commercial checks. An existing callback may be usable without creating a new subscription.

A revised release must demonstrate that the exact paid environment starts the commercial reconciliation worker, that the intended authenticated Google route persists accepted notifications, and that invalid notifications are denied. Reuse accepted provider and ledger evidence for unchanged behaviour. Then freeze the revised package for a fresh exact-hash decision. The original authority covers only the stopped package.

No public account, real purchase, pack allocation or publication occurred in this operation. Post-launch monitoring starts after an actual launch.
