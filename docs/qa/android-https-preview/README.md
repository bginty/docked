## Verification and device boundary

Notification preferences and two community Edge actions acquired a second global database connection from inside a transaction, deadlocking a one-connection pool. Rate budgets now commit before the business transaction, failed actions still consume their budget, and ingestion reuses its reserved connection. Separately, the login form's native pre-JavaScript fallback used GET. A fictional, intercepted browser probe confirmed that it could place field values in the URL. API forms now stay disabled until hydrated and explicitly use POST; other client forms also explicitly use POST. Both disposable QA passwords were conservatively rotated and all their sessions revoked; the durable tester was never used. The failed initial QA login did not retain enough evidence to prove whether that particular attempt used the fallback. See `qa-password-rotation.json` and the browser regression evidence.

## Maintenance boundaries

The canonical Preview alias is the installed APK's stable backend address. To update it, export reviewed tracked sources with `scripts/prepare-hosted-preview.mjs`, inspect the upload dry run, scan the exact export, deploy to this isolated project with the official Vercel CLI, and verify actual `target=null` (Preview) and `READY` before `scripts/configure-hosted-preview.mjs --assign-android-alias <id>`. Run its read-only `--audit` afterward. Never promote this deployment or reuse these variables in a production environment. Refresh the public Android deployment receipt from actual verification before a new hosted APK build.

The hosting setup deploys no general worker. Failed remote account erasure remains queued for an authorised retry worker, and quarantine expiry also requires a worker. Preview on-demand processing is deliberately bounded and is not a production delivery service. Supplier rights, real odds/results/history, legal/jurisdiction approval, forward validation, monitored operations and production signing remain separate release prerequisites.
