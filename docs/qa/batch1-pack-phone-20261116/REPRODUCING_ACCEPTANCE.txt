Database fixtures
The default suite uses PGlite for SQL contracts. Native marketplace and preserved-
collection suites require separate fresh disposable PostgreSQL clusters because
roles are cluster-wide and the migrations intentionally reject unknown existing
runtime-role grants. Use only the fixture's accepted 127.0.0.1 database naming
pattern with AUSTRALIAN_SALARY_TEST_DB. Native tests were run separately against
fresh postgres:17.11 containers, never against the restored/customer database.
Initial stale-fixture failures and their repaired reruns are retained in logs.
No migration guard was weakened to make a fixture pass.

uses savepoints for application transactions. It measures handler/SQL execution,

the 24-connection acceptance above. Hosted latency must be measured before any
promotion; local targets alone do not establish hosted performance.
