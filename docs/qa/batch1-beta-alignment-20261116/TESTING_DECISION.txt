1. DECISION
The existing invite-only Production beta is the real website/Android acceptance
environment. Preview is a short prerequisite for genuine hosted HTTP/Auth and safe
failure testing. It is not a second product, permanent testing platform or a copy
of all Production records. No new project, service or paid infrastructure is needed.

The exact previous 154-table fixture is NOT necessary. The smaller rehearsed option
has 143 dependency tables plus two access-control tables. A static dependency audit
shows the state table and its unchanged triggers alone reach 137 tables; actual pack
and Auth roots reach 143. Counts include financial/reservation/ownership guard
dependencies even when those features are disabled. Example:
beta_packs.capture -> commercial_billing.cards -> lineup_transfer_guard ->
card_entry_reserved -> beta_fantasy.competitions -> prize-template dependencies.
Those dependencies do not enable prizes or scoring. Removing those checks/stubbing
functions to make the count look smaller would not be equivalent verification.

145 is the smallest package actually rehearsed here, not a proof of the smallest
possible SQL graph. Further splitting legacy guard functions or reusing mixed-age
shared Preview objects would add a schema/security refactor to Batch 1. It is not
the shortest safe route. All namespace changes are disposable and isolated from
existing Preview accounts, Phone configuration and data.

What was removed:
- Nine collection/Weekly-reader tables and their hosted entrypoints.
- Preview-only collection/Weekly application context changes from c7e0fb00.
- Hosted UI clone, 900-card workload preconditioning and the large HTTP benchmark.
- The request to create 2,479 fictional players/6,540 definitions for hosted tests.
What remains:
- 108 fictional players, 540 definitions, two existing synthetic Auth accounts.
- 100,000 nonredeemable fixture credits per synthetic account, no top-ups.
- Twenty planned unique purchases, maximum allowance 24; original guards intact.
- Expiring restricted runtime/NOLOGIN owner, exact Preview target, MFA and allowlist.
- Pack HTTP only; other app surfaces are not exposed by this acceptance mode.
In the post-rehearsal fixture, 100 of the 145 tables are empty. No customer rows.
Frozen payload reduced from 669,899 to 137,416 bytes (approximately 80% smaller).
