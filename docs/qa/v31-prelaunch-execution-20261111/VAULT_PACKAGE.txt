Acceptance and recovery procedure
1. Fresh founder MFA session; verify independent recovery method without recording
   codes. Read back exact resource/version/config and effective IAM.
2. Access that exact canary version; compare digest in memory, emit pass/fail only.
3. Existing actual runtime/verifier/RTDN principals must be denied. Do not grant
   impersonation or access just to manufacture a test. If a real principal cannot
   be safely exercised, record that limitation rather than passing a simulation.
4. Wrong-version access must fail without falling back to latest.
5. Disable the canary version, prove denial, re-enable it, prove identical digest.
   Do not destroy any version or delete the whole secret as a test.
6. Correlate access/admin logs by principal, exact version and timestamp; never
   capture payload. Record denials separately if a particular denied request is
   not emitted by the service. Remove temporary grants and recheck final IAM.
7. Emergency: use founder's independent MFA/recovery method, revoke compromised
   secret-scoped access, disable the affected version if necessary, preserve logs.
   Whole-secret deletion is not protected by the version-destruction delay.
8. Separate live-key transfer approval later: map each encrypted archive to an
   exact vault version, test an isolated archive restore, preserve old versions
