DOCKED — POST-BETA OWNER LOGIN / LOADING FIX

Status: implemented and locally verified; Production deployment requires a new
exact-package approval. Public launch remains NO-GO.

Root cause
----------
The completed beta transition correctly denies beta gameplay to retained Owners.
However, /app still routed completed onboarding to /fantasy/play. A stale login
return URL and native session routing could repeat that route. The resulting
gameplay/wallet denial was displayed as a generic loading failure. In addition,
the global sport provider treated /admin as member gameplay and AdminShell did
not release the document startup overlay after client navigation.

Authenticated Vercel logs on 2026-11-17 at 06:21–06:22 UTC independently confirm
/fantasy/play authentication/service errors, /api/sports-beta access UNAVAILABLE,
/api/test-wallet service errors and, at 06:21:27 UTC, refresh_token_not_found on
/app/login. These are two related browser/route problems, not evidence that the
retained Owner identities were deleted. Both original identities, Owner roles,
individual verified TOTP factors and allowed transition records are intact.

Correction
----------
1. Derive postBetaOwner only after provider-verified identity, current Auth
   session, admission, transition and database Owner-role checks. No email,
   display-name, hard-coded UUID or editable profile metadata grants access.
2. During the existing closed beta runtime, ended-beta Owners land on
   /admin/incidents, through their existing MFA challenge when needed. Apply the
   same route to /app, old /fantasy bookmarks, login/MFA returns and native resume.
   All page/API role checks and the betaEnded gameplay prohibition remain.
3. Admin navigation no longer fetches beta sport capabilities or links retained
   Owners to retired profiles/wallets. AdminShell releases the startup overlay.
   MFA remains mandatory. The Owner label applies equally to Founder and Barry.
4. Preserve every SDK cookie update across callbacks/redirects. On a definitive
   provider rejection, remove only the matching project's browser session-cookie
   chunks and return protected GET pages to login. The installed SDK also clears
   its obsolete PKCE verifier. Do not log tokens, revoke other devices or clear
   sessions for provider outages, throttling or an insufficient MFA level.
