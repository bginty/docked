# Player trends — Phase 5C

The trend contract is descriptive research, not an implemented player-impact model. No player dataset, fitted coefficient, player probability adjustment or populated trend is installed by this change. A missing authorised statistic is unavailable, never zero.

`calculateResearchTrend` accepts resolved structured measurements and an explicit, versioned policy. The caller must first check current source rights, corrections, conflicts and player/event mapping. Every observation retains its fact, source version, match, occurrence, knowledge and ingestion times. Multiple source reports of one match must be resolved upstream; duplicate event measurements are rejected rather than counted as extra appearances.

Comparisons require the same player, metric, unit, competition, season, venue filter and opponent-adjustment version. The policy explicitly chooses DISJOINT (baseline precedes recent) or RECENT_INCLUDED_IN_BASELINE (for example, season-to-date containing the recent period). The latter discloses the overlap and both sample sizes; it cannot truncate the containing baseline with last-N. Evidence IDs remain unique and no significance claim assumes independent samples. There is no default last-five sample, half-life, minimum appearances, minimum minutes or meaningful-change threshold. A reviewed policy must set these. Optional last-N limits and exponential time weights are explicit and hashed. Per-90 rates additionally use minutes as exposure weights and require positive observed minutes; ordinary count observations use the declared match/time weighting.

ABOVE_BASELINE / NEAR_BASELINE / BELOW_BASELINE describe only the configured absolute or percentage threshold. They are not statistical significance, confidence, causal player impact, predictive advantage or expected goals added. With insufficient sample/exposure, values and label are unavailable. With a zero baseline, relative percentage and a percentage-based label are null; an absolute difference can still be reported. H2H and unadjusted form must remain display context.

The pure function does not fetch or store data, approve a source, activate a feature, publish content or alter Football V1. A future adapter must provide authorised statistics and reviewed mappings; the live read model must expose only source-permitted fields. Test measurements are explicitly authored fixtures and never member performance.
