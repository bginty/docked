Audio compared with V2
V2 used a small scheduled tone sequence for Legendary/Icon. V3 has six original
synthesised scores with filtered-noise whooshes, rising energy, stereo harmonics,
bass transients and rarity-specific endings. There are no downloaded recordings,
new services or audio-file downloads in the application.
Core: digital flip and two-note confirmation. Rare: whoosh and brighter shimmer.
Elite: rising layered energy, impact and sparkle. Ultra Rare: deeper bass and
detuned crystal resonance. Legendary: longer cinematic charge, deep impact and
golden chord. Icon: distinctive three-note ascent, deepest impact and diamond finish.
Charge, flip and arrival cues follow actual CSS animation-start events. The impact
is aligned to the Canvas midpoint flash. One AudioContext is reused across a pack.
Skip/advance cancels pending notes; mute, backgrounding and closing release resources.
Sound remains opt-in. Reduced motion uses the existing quiet/static presentation.
Offline stereo exports are 268–961 KB for review only. Application audio is generated.
Six measured mono peaks: 0.256, 0.317, 0.242, 0.235, 0.225, 0.213; no clipping.
Measured RMS spans about 1.1 dB. This is not a formal LUFS or listening-panel assessment.

Performance and limitations
Canvas sprite caching and orbit calculations are shared. Near-transparent sprites are
skipped. Adaptive rendering lowers particle budgets and backing resolution under load.
Hidden tabs stop the loop; reduced motion renders a static scene.
The equal-window desktop/mobile-viewport run measured 58.1–59.6 fps for Rare through Icon,
0.41–1.46 ms average Canvas draw, and 49.4–50.9 fps under 4x CPU slowdown with automatic
balanced quality. Core's first development-page run contained an approximately 865 ms
stall and averaged 48.7 fps; the p95 frame interval was 16.8 ms. Raw results are retained.
An isolated production-mode fixture measurement investigates that development startup outlier.
These are Windows browser measurements, not Samsung hardware results.
ADB reported no connected device. No physical Android playback, speaker or native-share
acceptance is claimed. The installed app receives web changes; no new AAB is deployed.
The optional native image-share plugin inherited from V1 requires a compatible future
Android build; current builds keep the existing web sharing/download fallback.

Release procedure
1. Commit the checked presentation, tests and scripts; push the release branch.
2. scripts/cinema-v3-release.mjs prepare verifies the live baseline and exports immutable Git source.
3. Stage with --prod --skip-domain; the docked.com.au alias remains on the current release.
4. Verify build, source identity, closed gates, policies, authentication denials, six hosted
   rarity styles and unchanged schedules using scripts/cinema-v3-verify-release.mjs.
5. Promote only after these checks pass. Verify again with --live.
6. If a critical regression occurs, restore deployment dpl_2YxdbcCi584D1zQPVmyewM8QPxiQ.
   No database rollback is needed because this release has no data/schema mutations.

The staged/live JSON records under docs/qa/cinema-v3-release are the authority for
actual deployment status and SHA. This document alone does not assert deployment success.
